总体架构

Architecture Overview

1.1 系统定位

山东高速集团AI平台是集团数字化转型的核心能力底座，以"运营垂域大模型 + RAG知识库"为双引擎，向上支撑收费、养护、能源、绿通、服务区、出行服务等业务场景的智能化升级。

核心定位：不是单点AI工具，而是"基础能力平台 + 场景智能体"的双层架构。基础能力平台统一建设大模型、知识库、数据标注、Prompt工程等可复用能力；场景智能体基于平台能力快速孵化，面向具体业务落地。

1.2 设计原则

原则说明实现方式
能力沉淀通用AI能力统一建设，避免各项目重复造轮子AI能力平台化，通过API/SDK向上输出
数据驱动模型效果依赖高质量行业数据建立多模态数据标注体系和数据飞轮机制
安全可控国企场景对数据安全和模型可控要求高私有化部署、可解释性输出、人工兜底机制

开放生态支持第三方智能体接入和扩展标准化智能体接口，AI门户统一纳管

2.1 垂域大模型微调模块 核心底座
负责人：刘树港 周期：2026.05 – 2026.12

2.1.1 模块定位与目标

在通用大模型基础上，注入高速运营领域知识，训练出具备行业理解能力的运营垂域大模型。核心目标：

  • 理解高速运营领域术语（如绿通、门架、稽核、锥桶、事件调度等）
  • 掌握运营管理制度、应急预案、操作规程等知识
  • 在运营问答、文案生成、数据分析等场景效果优于通用模型
  • 支持私有化部署，数据不出域

2.1.2 微调策略

方法适用场景数据量需求GPU资源优先级
LoRA / QLoRA 领域知识注入、风格对齐 5,000 – 50,000 条 单卡A100 80G P0 · 首选方案
全参数微调 (Full FT) 深度领域能力塑造 10万+ 高质量数据 4-8卡A100 P2 · 后期视效果
DPO / RLHF 回答偏好对齐、决策质量优化 成对偏好数据 2-4卡A100 P1 · Q4启动
继续预训练 (Continual PT) 领域术语/知识体系构建 GB级行业文本 8卡A100+ P3 · 资源允许时
推荐路径：第一阶段用LoRA做SFT（监督微调），快速验证效果；第二阶段叠加DPO做偏好对齐；后续根据业务效果决定是否做全参微调。

2.1.4 评估体系

模型上线前必须通过以下评估：

  • 客观指标：CEval/CMMLU行业子集准确率、MMLU、BLEU/ROUGE（文本生成类）
  • 垂直评测集：自建高速运营领域QA评测集（≥500题），覆盖收费、养护、路政、服务区等
  • 人工评估：业务专家盲评（至少3人交叉），维度包括准确性、相关性、专业度、安全性
  • 安全测试：越狱测试、敏感内容输出检测、幻觉率统计
2.2 运营知识库（RAG）模块 核心底座
负责人：刘树港 周期：2026.05 – 2026.11

2.2.1 模块定位

作为AI平台的"企业记忆"，存储并检索运营领域的结构化和非结构化知识，通过RAG（检索增强生成）技术为大模型提供精准知识，减少幻觉，提升回答可信度。 支持"行业公共知识库 + 团队/个人私有知识库"双层体系。

2.2.4 文档处理流水线

文档上传 → 格式校验 → 文档解析 → 内容清洗 → 分块(Chunking) → 向量化(Embedding) → 写入向量库
                                  │
                                  ├─ PDF/Word/PPT/Excel/图片/音频
                                  ├─ 保留标题层级、表格结构、代码块
                                  └─ OCR处理扫描件和图片文档

分块策略：
  • 基础分块：512 tokens / 块，重叠128 tokens
  • 语义分块：按语义段落边界切分（推荐用LangChain SemanticChunker）
  • 结构化分块：表格、列表、章节单独处理，保留结构信息
  • 元数据注入：每块附带文档名、章节、页码、更新时间

质量控制：
  • 分块后质量抽检（覆盖率、语义完整性）
  • Embedding相似度校验（同一文档相邻块cosine ≥ 0.85）
  • 检索准确率月度评估（MRR@5, Recall@10）

2.2.6 引用溯源

回答必须附带引用来源，支持点击跳转原文片段：

  • 每个答案片段标注引用编号 [1] [2]
  • 引用卡片显示：文档名称、章节/页码、原文片段、上传时间
  • 置信度低于阈值（如0.5）的引用标记为"低置信度"
  • 引用信息持久化，支持事后审计和溯源
2.3 异常指标AI告警模块 场景应用
负责人：孙宁波 周期：2026.06 – 2026.10

2.3.1 模块定位

替代传统阈值告警，基于AI算法对全量运营指标进行智能异常检测，实现更精准的告警（减少误报漏报），并提供根因溯源和影响范围分析能力。

2.3.2 算法设计

采用"多算法融合 + 规则校验"的架构：

算法检测能力适用指标类型实现方式
3σ / 四分位法基础异常点检测平稳波动指标统计方法，实时计算
同比/环比异常偏离同期正常水平有明显周期性指标周同比、日环比、月环比
趋势漂移检测指标渐变式偏离基线缓慢恶化类指标滑动窗口斜率检测
突变检测阶跃式突增/突降突发事件类CUSUM / Pettitt检验
Prophet预测偏离预测区间趋势+季节性指标Facebook Prophet
LSTM/AutoEncoder复杂时序模式异常多变量关联指标深度学习模型
融合策略：多算法独立检测 → 投票/加权融合 → 规则引擎校验（节假日、特殊事件、已知维护期等排除）→ 生成最终告警。

2.3.3 告警分级与推送

级别定义推送通道响应要求
P0 紧急核心指标严重异常，可能影响安全或重大经济损失电话+短信+企业微信@全员15分钟内响应
P1 重要主要指标明显异常，需及时处理企业微信群@负责人2小时内响应
P2 一般指标轻度偏离，关注即可系统通知+日报汇总当日关注
P3 提示趋势性变化，提前预警周报/月报汇总规划性处理

2.3.4 根因溯源

告警触发后自动执行根因分析：

  • 相关性分析：计算告警指标与其他所有指标的时序相关性，找出同步异动指标
  • 下钻分析：按维度（路段、收费站、车型、时段等）逐层下钻定位
  • 事件关联：与同期事件（事故、施工、天气、管制等）做关联匹配
  • 大模型解读：调用垂域大模型生成自然语言原因分析报告
2.4 高速公路运营调度智能体 场景应用

6.2 上线标准

AI功能上线必须满足以下条件：

  • 功能完备性：需求规格书中P0/P1功能全部实现并通过测试
  • 效果达标：模型/算法在行业评测集上达到预设指标
  • 安全性：通过安全测试，无高危和严重漏洞
  • 性能：满足并发量和响应时间要求
  • 可观测性：日志、监控、告警完善，可追踪可排查
  • 回滚方案：有明确的回滚方案和应急预案
  • 用户培训：目标用户完成使用培训
  • 灰度验证：经过灰度环境小流量验证不少于7天
